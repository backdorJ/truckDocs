# TruckDocs — счёт и акт из договора-заявки

Берёт договор-заявку (PDF) и карту предприятия заказчика (DOCX), вытаскивает данные
и формирует счёт и акт в DOCX. Сторонних NuGet-пакетов нет.

## Запуск

```bash
# 1. Нужен pdftotext (poppler):
#    Windows: choco install poppler    macOS: brew install poppler    Linux: apt install poppler-utils
# 2. Профиль перевозчика: скопировать и заполнить реквизиты ИП и банк
cp carrier.example.json carrier.json
# 3. Прогнать на заявке
dotnet run --project src/TruckDocs.Cli -- заявка.pdf карта.docx
```

Опции: `--carrier path.json`, `--out папка`, `--number 3` (номер документа вручную), `--date 27.11.2026`.
По умолчанию дата документов — дата выгрузки, номер — следующий по счётчику `out/numbering.json` (`N-ГГГГ`).

Для заявок чужой формы: задать `ANTHROPIC_API_KEY` — тогда, если шаблонный парсер заявку не узнал,
она разбирается через LLM (`LlmOrderExtractor`).

## Структура

| Проект | Что внутри |
|---|---|
| `TruckDocs.Core` | Модели (рейс, контрагент, заявка), интерфейсы, `TripBuilder`, сумма прописью, проверка ИНН/БИК/р/с |
| `TruckDocs.Parsing` | Текст из DOCX/PDF, парсер карты предприятия, шаблонный и LLM-парсер заявки, `OrderPipeline` |
| `TruckDocs.Documents` | Генератор DOCX без зависимостей, счёт и акт |
| `TruckDocs.Cli` | Консольная обёртка для проверки на реальных файлах |

Ключевые интерфейсы: `IOrderSource` (откуда пришла заявка: почта, Saby), `ITextExtractor`,
`IOrderExtractor` (шаблон / LLM), `IDocumentGenerator` (счёт, акт, позже УПД).

## Что проверяется автоматически

- ИНН заказчика (контрольная сумма), р/с и корр. счёт против БИК (ключ ЦБ);
- ИНН в карте совпадает с ИНН в заявке, госномер в заявке совпадает с профилем;
- штрафы и условия ответственности из заявки выводятся как предупреждения;
- срок оплаты считается от даты выгрузки по условиям заявки (рабочие/календарные дни).
